# Architecture

How the NextInML site is put together. For setup and commands, see the root `README.md`.

## Overview

NextInML is a static Astro site. Content is read from files in `content/` at build time, checked against a schema, and rendered to HTML. Nothing runs on a server after the build. The only JavaScript sent to the browser is the React filter bar on `/programs`.

## Content

Two collections, defined in `src/content.config.ts`:

- `programs`: one YAML file per program in `content/programs/`. The file name is the id. The schema uses enums for `type`, `region`, and `format`, so the filter options stay consistent and a typo fails the build.
- `writeups`: one Markdown file per writeup in `content/writeups/`. The `program` field is a reference to a program id. Files starting with `_` are ignored, which keeps the template out of the site.

Astro only logs a warning for a broken reference, so `assertWriteupsHavePrograms` in `src/lib/content.ts` throws during the build when a published writeup points at a missing or draft program.

`lastVerified` is optional and has no default. A listing without it shows as "Not verified" rather than borrowing a date nobody checked.

## Code layout

- `src/lib/content.ts`: the only code that queries collections. `getPrograms()` returns published programs as plain `Program` objects (dates as ISO strings) in display order: open deadlines soonest first, then rolling, then closed. `getWriteups(id)` returns one program's writeups, newest first.
- `src/lib/programs.ts`: the `Program` type and label helpers (`verifiedLabel`, `isStale`, `deadlineState`, `deadlineCta`, `deadlineLabel`). It does not import `astro:content`, so the React island can use it.
- `src/pages/`: `index.astro` (home), `programs/index.astro` (directory), `programs/[id].astro` (one page per program, generated by `getStaticPaths`), and `404.astro`.
- `src/components/`: `ProgramDirectory.tsx` is the island. It renders `FilterBar.tsx` and a grid of `ProgramCard.tsx`. `ProgramCard` is a React component that Astro also renders to static HTML on the home page. The rest are server-only Astro components: `Nav`, `ThemeToggle`, `Writeups`, `Mark` (the Tessellate logo) and `Pattern` (the tiled brand background).
- `src/layouts/Base.astro`: the HTML shell, meta tags, nav, and footer.

## The filter island

`/programs` is prerendered with every program listed, so the page works without JavaScript. After hydration, `ProgramDirectory` reads `type`, `region`, `format`, and `deadline` from the query string and writes changes back with `history.replaceState`. A filtered view can be shared or bookmarked.

## Build-time dates

The "Closed" state, the vermilion out-of-date marker, and the order of programs are computed when the site is built. CI rebuilds daily so these stay within a day of correct.

## Freshness

`scripts/check-stale.mjs` reads the YAML directly (no Astro) and reports listings to re-check. The weekly `stale-check` workflow runs it and keeps one GitHub issue updated. To spot changed program pages, it hashes each page's visible text and keeps the hashes between runs in the Actions cache. Pages with rotating content can trigger false "changed" flags.

## Theme and brand

The brand is "G · Tessellate": ultramarine `#2335C9`, vermilion `#F2542D`, ink `#121212`, paper `#F7F7F5`, Alexandria for Latin and Arabic, square corners. All colours are CSS variables in `src/styles.css`, with a light set on `:root` and a dark set on `[data-theme="dark"]`. Components use the Tailwind names mapped to them (`bg-surface`, `text-primary-text`, `text-subtle`, `text-vermilion`, and so on), so a component never hard-codes a theme.

An inline script in `Base.astro` sets `data-theme` on `<html>` before first paint, from the saved choice or else the OS setting. `ThemeToggle` flips it and saves to `localStorage`. With JavaScript off, a `prefers-color-scheme` media query applies the dark values.

## Hosting

`wrangler.jsonc` deploys `dist/` to Cloudflare as a static-assets Worker with no script. Unknown paths serve `dist/404.html`.
